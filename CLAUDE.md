The **backend is the evaluated deliverable**; the React app is a dispatch-board harness that exercises the real API. The brief is at `../docs/KeyloopCodingChallange.pdf` (outside the repo). `docs/SYSTEM_DESIGN.md` is the source of truth and must stay consistent with the code:

- `docs/SYSTEM_DESIGN.md` - domain model, availability algorithm, concurrency strategy, API/problem catalogue, environments, security, observability, ADRs. Read §5–§8 before touching backend code.
- Code comments that cite "Addendum A/B/C §..." refer to the author's planning addenda (A reflection/AOT, B OpenAPI/UI, C Aspire), which are local notes and not in the repository; the ADRs in `docs/SYSTEM_DESIGN.md` §18 are their committed equivalents.

## Commands

Prerequisites: .NET SDK 10.0.100 (`global.json`), Node 22 + pnpm, and a running Docker daemon. The AppHost uses the Aspire CLI bundle for DCP and the dashboard; an installed Aspire CLI or the SDK's DNX package download resolves it on first run. Aspire CLI 13.6.0 on this machine starts the 13.6.1 AppHost with its 13.6.0 DCP/dashboard bundle without extra setup; publishing can use `dotnet dnx --yes aspire.cli@13.6.1 -- publish --apphost src/Keyloop.ServiceScheduler.AppHost -o artifacts/compose` for a matching CLI. On this machine Docker is provided by **Colima**: `colima status` and, if stopped, `colima start --cpu 4 --memory 6 --disk 40`.

The root `aspire.config.json` selects the C# AppHost for plain CLI commands. `aspire publish` generates Compose YAML and `.env`; it does not build images, fill secret inputs, or create EF migration bundles. Web is always in the model, and Aspire 13.6.1 generates `WEB_IMAGE` from its committed Dockerfile. Use `aspire deploy` for the managed build/deploy pipeline, or build both Dockerfiles and supply `API_IMAGE`, `WEB_IMAGE`, and `POSTGRES_PASSWORD` before manual `docker compose --env-file artifacts/compose/.env -f artifacts/compose/docker-compose.yaml -p keyloop-demo up -d`; `POSTGRES_USER` may stay empty (the Compose file defaults it to `scheduler`). Discover the web host port with the same Compose arguments followed by `port web 8080`. For isolated verification, publish with `-- --AppHost:UsePersistentResources=false` and a fresh Compose project name, then use those same arguments for `down --volumes --remove-orphans`; never use or remove the developer's database volume. The README gives the full manual sequence. UAT/Production migration bundles are a separate release step (`dotnet ef migrations bundle --project src/Keyloop.ServiceScheduler.Infrastructure --startup-project src/Keyloop.ServiceScheduler.Api`).

The Demo bundle creates `schedulerdb` on an empty PostgreSQL data directory via `POSTGRES_DB`, runs migration and seeding, and serves Scalar over HTTP. Web publishes a dynamic host port targeting nginx's 8080; `API_UPSTREAM` comes from `api.GetEndpoint("http")` and renders as `http://api:8080`. nginx proxies `/api`, `/openapi`, and `/scalar` with the URI unchanged. Its dedicated Compose network is `172.30.14.0/24`, the sole trusted network in `appsettings.Demo.json`. Change both together if that subnet conflicts locally (`AppHostModelTests` fails while they differ), and keep the API unpublished on that network: the trusted /24 includes the bridge gateway, which carries traffic from published host ports. Web is the browser entry point and supplies the trusted last forwarding hop. UAT/Production require explicit ingress trust configuration. Aspire's automatic forwarded-header injection is disabled so the API's validated policy controls trust. Readiness probes use the API's HTTP endpoint, so they do not require trusting the development certificate; Scalar still links to HTTPS when available.

For a fresh, isolated AppHost verification, supply a temporary password and disable persistence: `dotnet run --project src/Keyloop.ServiceScheduler.AppHost -- --AppHost:UsePersistentResources=false --Parameters:postgres-password=<temporary-password>`. Stop the AppHost after the check; its session containers are removed. The supplied password prevents evaluation or persistence of the generated default. Keep ordinary development runs on the default persistent resources.

## Architecture in one screen

- **Vertical slices, no mediator.** `src/Keyloop.ServiceScheduler.Api/Features/<Capability>/<Slice>/` holds the endpoint (implements `IEndpoint`, listed in `EndpointRegistry`, which maps it into the `/api/v1` group), request record, FluentValidation validator (applied by `ValidationFilter<T>`), handler (plain class registered in DI), and response records. Handlers query `SchedulerDbContext` directly; there is no repository layer.
- **Domain is persistence-ignorant.** `src/Keyloop.ServiceScheduler.Domain/` contains aggregates (`Appointment`, `Dealership`), entities (`ServiceBay`, `Technician`, `ServiceType`), value objects (`TimeSlot`, `Vin`, `ServiceDuration`, `OperatingHours`) and domain services (`AvailabilityCalculator`, `AllocationPolicy`, `BookingWindowPolicy`). It never references EF Core or ASP.NET Core. Rule violations throw `DomainRuleViolationException(ruleCode, …)` whose `ruleCode` is the problem slug (→ 422); illegal lifecycle calls throw `InvalidStateTransitionException` (→ 409).
- **Assembly boundaries (ADR-025).** Api references Domain and Infrastructure; Infrastructure references Domain only; Domain references no project or package. Persistence, migrations, seeding, notification and triage adapters live in `src/Keyloop.ServiceScheduler.Infrastructure/`. The design-time factory and migrations belong to the DbContext assembly. Api retains the composition root, Common web concerns and every complete vertical slice; no Service/Application project or repository layer. `DatabaseOptions` lives in Infrastructure/Persistence and notification options/validators in Infrastructure/Notifications; binding stays in Program.cs. `CurrentActor` is audit state in Infrastructure/Persistence/Interceptors, populated by Api middleware.
- **Concurrency model (do not weaken):** the overlap invariant lives in PostgreSQL as two partial GiST **exclusion constraints** on `appointments(bay_id, time_range)` and `(technician_id, time_range)` over a stored generated `tstzrange`. `BookAppointmentHandler` runs at **`READ COMMITTED`**, takes `pg_advisory_xact_lock(dealershipKey)` first, then checks and inserts. A booking transaction must never take a second contended lock or perform a second contended insert, with one scoped exception: the idempotency-key row, which only the same key used at another dealership can contend, and the lock holder never waits on its own lock's waiters (ADR-003). The appointment id is minted once outside the execution strategy and a lost commit acknowledgement is resolved by `verifySucceeded` plus an in-attempt id check (§7.3, §7.5). `xmin` is the concurrency token for state transitions (a stale cancel is `409 concurrency-conflict`; a cancel's lost commit acknowledgement is verified by the `xmin` it wrote, and only the runs after an in-doubt commit lock the row, §7.3 layer 3). `PostgresErrorClassifier` is the single place SQLSTATEs are interpreted.
- **Time:** UTC `DateTime` everywhere in code and DB; dealership `TimeZoneId` (IANA) drives operating hours via `LocalTimeConverter` (DST gap → first valid instant, ambiguity → earlier instant). Half-open intervals. Inject `TimeProvider`; never call `DateTime.UtcNow`.
- **Errors:** RFC 9457 ProblemDetails with types under `https://api.keyloop.example/problems/<slug>`; 400 = malformed, 422 = business rule, 409 = state conflict (`slot-unavailable`, `slot-conflict`, `invalid-state-transition`, `concurrency-conflict`). `GlobalExceptionHandler` is the only mapper.
- **Audit/events:** aggregates raise domain events; `DomainEventInterceptor` writes `appointment_history` rows in the same transaction and stages booking/cancellation email in `notification_outbox` in the same SaveChanges as a JSON snapshot of the aggregate (ordinary fresh-id inserts, no lookup or rendering in the transaction, ADR-003/020), and notifies `IDomainEventObserver`s after commit (one of them nudges the dispatcher). A BackgroundService wakes on that nudge, the next due row or a 15-minute idle interval, claims due rows with SKIP LOCKED, commits a lease, renders the email and sends via MailKit, and acknowledges with the claim token. Retry exhaustion or an unrenderable row is a manual dead letter; delivery is at least once, correlated by the `X-Keyloop-Notification-Id` header (SMTP also derives Message-Id from the outbox id). Emails never contain visitor-typed free text (cancellation reason, customer name). Rows for reserved domains (`example.com`, `.test`, ...; every seeded customer) are staged `Suppressed`, counted and logged after commit, and never become backlog (the claim re-checks older Pending rows). The backlog gauges work with dispatch off. Cloudflare is reserved and fails clearly at startup until its adapter exists.
- **Booking intake triage (ADR-026):** Api `Features/Triage` keeps the two complete slices and thresholds; Infrastructure `Triage` owns the typed Cloudflare `/ai/run` client, source-generated JSON, closed service rubric and answer validation. `ServiceCatalogueReader` shares bookability with the catalogue slice. Disabled by default, optional AppHost parameters only; descriptions never enter storage, logs, spans or metric tags. Normal integration verification excludes `Category=LiveAi`; only the stakeholder can authorize the opt-in golden set or public enablement.
- **Telemetry:** Api `SchedulerTelemetry` owns the `ActivitySource` and request instruments; Infrastructure `InfrastructureTelemetry` owns the shared `Meter` and notification instruments, all named `Keyloop.ServiceScheduler`; ServiceDefaults wires OTLP to the Aspire dashboard. Metric names are part of the design (§12) - do not rename.
- **Contract sync:** `dotnet build` of the API writes `contracts/openapi/v1.json` (commit it); `OpenApiContractTests` asserts the runtime document equals that file; HeyAPI (`openapi-ts.config.ts`) generates `src/api/*.gen.ts` including TanStack `queryOptions`/`mutationOptions`. Operation ids (`BookAppointment`, `GetAvailability`, …) are stable API.
- **Environments:** `Development` (migrate + seed on startup, Scalar on), `SystemTest` (integration tests; rate limiting off), `UAT`/`Production` (migration bundles, no seed, Scalar off in Production), and `Demo` (only for the Aspire-published compose bundle: UAT posture plus migrate/seed at startup).
- **Aspire (ADR-019):** the AppHost owns secrets (generated `postgres-password` parameter persisted to user secrets - never put credentials in appsettings), persistent PostgreSQL + pgweb, health-gated startup, `pnpm install --frozen-lockfile` for the web app, `API_HTTP` service discovery for the Vite proxy, publish-time `API_UPSTREAM` discovery for nginx on port 8080, browser OTLP to the dashboard (dev only), and the *Reseed demo data* dashboard command (`POST /api/v1/admin/demo/reseed`, key-protected, excluded from OpenAPI). Behaviour differs only via `appsettings.{Env}.json` and options classes validated on start.
- **OpenAPI (ADR-008/017/018):** the document is generated at build time into `contracts/openapi/v1.json` (while `BuildTimeOpenApi.IsActive`, `Program.cs` runs in Development with a placeholder connection string and skips database work); summaries, response docs and request examples come from XML comments on static handler methods and DTOs; Scalar at `/scalar/v1` is the API test UI (not mapped in Production). Endpoint rules the contract tests enforce: `.WithName("<OperationId>")` (append new ids to `OpenApiContractTests.OperationIds`); every endpoint declares `.ProducesRateLimitedProblem()` plus a `<response code="429">` comment (the global limiter covers every route); a request body is described by `[Description]` on its parameter, not by `<param>` (the 10.0 XML generator copies every unmatched `<param>` onto the body; `SchedulerOpenApi.DescribeRequestBody` restores the attribute's text and fails generation without one); every response type is listed in `OpenApiContractTests.ResponseTypes`.
- **Reflection budget (ADR-016):** no assembly scanning or reflection-based discovery; endpoints are listed in `EndpointRegistry`, handlers and validators are registered explicitly; every HTTP DTO (and top-level `IReadOnlyList<T>`) is listed in `Common/Serialization/SchedulerJsonContext.cs` because reflection-based JSON is disabled; mappers are Mapperly-generated (`RequiredMappingStrategy.Target`); options are validated by `[OptionsValidator]`; HTTP JSON stays in Api `SchedulerJsonContext`, while Infrastructure `Serialization/PersistenceJsonContext` owns audit/outbox JSON; logs go through assembly-owned `[LoggerMessage]` methods in Api `SchedulerLog` and Infrastructure `Telemetry/InfrastructureLog` with stable event ids and names; the Request Delegate Generator is on, so an endpoint it cannot intercept fails the build. Residual reflection (EF Core, FluentValidation) is measured by `scripts/aot-readiness.sh`.
- **Frontend conventions** follow the shadcn dashboard template (Vite variant): Base UI primitives, `cn` from the `cn` package inside `components/ui`, `@/` alias, Tailwind v4 tokens in `src/index.css`. Vite proxies `/api`, `/openapi`, `/scalar` to the API (no CORS in dev). Aspire sets `PORT` and the API's address as `API_HTTP` (via `WithReference(api)`), which `vite.config.ts` uses as the proxy target.

## Working rules specific to this repo

- Keep `docs/SYSTEM_DESIGN.md` and the code in agreement; if a design decision changes, update the ADR table in the same commit.
- Test names describe behaviour (`Rejects_off_grid_start_422`); domain tests use `FakeTimeProvider` at `2026-10-12T08:00:00Z` and book on `2026-10-13`.
- The AppHost smoke test lives in `tests/Keyloop.ServiceScheduler.AspireTests`, not in the integration tests: Aspire.Hosting needs reflection-based JSON, which the integration test process disables to mirror the API (ADR-016). It supplies the database password, clears optional triage parameters and strips persistence, so it never evaluates or writes the persisted password default and never mounts `keyloop-scheduler-pgdata` (configuration can still load user secrets). Create/build/start/API and web readiness share a five-minute deadline; failed setup and failed stop both dispose the application, with stop bounded to 30 seconds. The web check requests `/api/v1/dealerships` through Vite and asserts JSON with the exact seeded names. On macOS, create `/tmp/kl15c` and set `TMPDIR=/tmp/kl15c` for every `dotnet test` to keep MTP pipe paths short.
- Integration tests need Docker; the concurrency test runs five rounds and its assertions are not to be loosened - a failure is a design defect.
- The reference clones live outside the repo (`../references/`, provenance table in the README's licence section); the AGPL one (MiroTalk) must never be copied.
- Commit messages: Conventional Commits, ending with exactly one `Co-Authored-By` trailer for the current author; Codex uses `Co-Authored-By: OpenAI Codex (gpt-6.1-sol) <noreply@openai.com>`.
- When interacting with Cloudflare, use the `cf` CLI unless the project has a
  Wrangler configuration file.
